# Practice and live modes, certificate uploaded from Settings

Follows [`2026-11-11.dev-makefile`](2026-11-11.dev-makefile.WIP.md), where the question came up. Relates to section 5 (AEAT integration) of [`ROADMAP/2026-11-11`](../ROADMAP/2026-11-11/README.md).

## 2026-11-11: Decisions and implementation

Author's instructions: AEAT sending stays in test mode (against the mock) until a certificate is assigned; then live mode can be turned on. The certificate is uploaded from Settings. Test mode is only for practising. Not answered: whether live mode goes straight to production; kept `VERICOUNT_AEAT_ENV` (`test` = AEAT pre-production, `production`) for where live records go.

Naming: "practice" and "live" in code; "modo de prueba" and "modo real" in the interface, to avoid confusion with the AEAT test environment.

- Migration `0006`: `live` column on `invoices`, `billing_records` and `aeat_submissions` (default false: existing rows are practice). The unique keys of numbering and chain include `live`, so each mode has its own numbering and chain; a foreign key `(invoice_id, live)` keeps a record in its invoice's mode. `live_mode` (singleton, insert-only, who and when, NIF) and `aeat_certificate` (singleton; SELECT, INSERT and DELETE for the app role so a replaced or removed key does not stay behind).
- Mode is read from the database in every request; writes read it inside the chain lock, which activation also takes, so no invoice is issued in the mode that is ending.
- Practice records go to `vericount-aeat-mock` running inside the server on a loopback port (now a normal dependency of the server). The mock keeps state in memory, so on start it is restored from the stored practice results (`Mock::restore`): last answered hash, registered and cancelled invoices. Without that, the first practice record after a restart was rejected as a broken chain (checked by disabling it: the test fails).
- This changes a roadmap rule ("the mock must be unreachable from the production configuration"): it now holds for live records only. Practice records are not real and never go to the AEAT; live records never go to the mock in production (`VERICOUNT_AEAT_ENDPOINT` is still refused there).
- Certificate: PKCS#12 (`p12-keystore`, legacy RC2/3DES included, as FNMT exports) or PEM; converted to PEM, checked with `reqwest::Identity::from_pem`, refused when expired. Encrypted with XChaCha20-Poly1305 under `VERICOUNT_SECRET_KEY` (64 hex digits). Not checked: that the key matches the certificate; a mismatch shows up as a TLS error when sending.
- `AeatService` holds the settings and the current submitter, rebuilt on start and after upload, removal or activation. The submission loop asks it each round. Live mode without a certificate: nothing is sent, records wait.
- Activation (`POST /api/aeat/live`) needs a valid certificate and the software producer (`VERICOUNT_SOFTWARE_PRODUCER_NAME`/`_NIF`); practice uses a placeholder producer. It is irreversible.
- After activation practice invoices are hidden (404), numbering and chain restart, NIF locked. Before it, the NIF can change even with practice invoices.
- Removed `VERICOUNT_AEAT_SUBMIT` and `VERICOUNT_AEAT_IDENTITY_PEM` (the server warns if set). Installer generates the key (also for existing settings, on update), compose requires it, the chart generates it once (`lookup`) or takes `secretKey`/`existingSecret`.
- Interface: practice notice on Home and Invoices, "de prueba" tag and "FACTURA DE PRUEBA, SIN VALIDEZ" stamp on the printable invoice, Settings with certificate upload/removal and activation with confirmation. Practice QR codes always use the pre-production URL.

Checked: 75 tests (6 new in `tests/modes.rs`), fmt, clippy, shellcheck, `helm lint`/`template`. In the browser with `make up` and an OpenSSL `-legacy` .p12: wrong password refused, upload, activation, empty invoice list afterwards.

Open:
- The software producer is the author of vericount, the same for every installation; it could be built into the binary instead of configured.
- In practice mode the record state reads "enviada" though it went to the mock; the notice above the list explains it.
