## 2026-11-11: Workspace, server skeleton, CSP tests and CI

Done:

- Cargo workspace (`crates/*`), toolchain pinned to Rust 1.97.0, `unsafe_code` forbidden.
- `crates/server` (`vericounts-server`): Axum 0.8 + Tokio. `GET /healthz`, static files from `web/`, and one middleware (`security::headers`) that sets the security headers on every response, including 404s and static files.
- CSP: `default-src 'none'`, `script-src 'self'`, `style-src 'self'`, no `unsafe-inline`/`unsafe-eval`, `require-trusted-types-for 'script'` and `trusted-types 'none'` (no policy may be created yet).
- Tests (`crates/server/tests/security.rs`): the CSP is strict, the headers are present on every kind of response, and the HTML in `web/` has no inline scripts, styles, event handlers or `javascript:` URLs.
- Placeholder web client in `web/` (external module script and stylesheet only).
- GitHub Actions CI (`.github/workflows/ci.yml`): fmt, clippy with `-D warnings`, tests. Runs on pull requests and on pushes to `main`.
- Manual check in headless Chromium: the page loads with no CSP errors, and Trusted Types blocks HTML insertion and inline script creation.

Decisions taken, pending confirmation by the author:

- Axum + Tokio was "Proposed" in the roadmap; the skeleton uses it. SQLx is not added yet.
- HSTS is always sent; it only has an effect over HTTPS.

Findings on jq79 and strict CSP (inspection of the npm package `jq79@0.7.11`, not yet tested in a browser):

- The runtime falls back to `new Function` for template expressions, which `script-src 'self'` blocks. It has alternatives: a precompile step (`jq79/precompile`, Vite plugin), a nonce-based path and a service worker (`jq79-sw.js`). Its README points to `docs/csp.md` (`safeEval`), which is not in the npm package.
- It assigns `innerHTML` (after its own sanitizer) and has no Trusted Types support, so `trusted-types 'none'` will make it throw. Options: add a named policy to jq79 and allow that name in the CSP, or define a `default` policy.
